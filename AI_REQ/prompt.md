Ты — опытный разработчик на Python. Тебе нужно создать с нуля полноценное веб-приложение на FastAPI для управления AI-агентами (flow) из Langflow. Приложение должно содержать:

1. Публичную страницу (дашборд), где отображаются только опубликованные агенты.
2. Административный интерфейс для управления публикацией агентов.
3. Страницу чата с выбранным агентом.
4. Аутентификацию через LDAP.
5. Хранение статусов публикации в PostgreSQL.
6. Интеграцию с Langflow API для получения списка flow и их запуска.

- SQLAlchemy (асинхронный) + asyncpg
- PostgreSQL (использовать схему и модели)
- Jinja2 шаблоны

- httpx/requests для запросов к Langflow
- python-dotenv для настроек
- uvicorn для запуска

### Требования к функционалу

**1. Аутентификация и сессии**
- LDAP-сервер (тестовый) доступен по адресу `localhost:389`, base DN: `ou=users,dc=example,dc=com`, администратор: `cn=admin,dc=example,dc=com` с паролем `password`.
- Использовать библиотеку `ldap3` (не `python-ldap`).
- При входе в админку проверять пароль через привязку к LDAP.
- Сессии реализовать через подписанные cookies (itsdangerous).
- Все маршруты `/admin/*` защищены middleware: если нет сессии — редирект на `/auth/login`.
- Страница логина — простая HTML-форма с полями username/password.
- После успешного входа — редирект на `/`.
- Использовать систему могут только авторизованные пользователи через ldap.

**2. Работа с Langflow**
- Langflow API доступен по адресу из переменной окружения `LANGFLOW_URL` (по умолчанию `http://localhost:7860/api/v1`).
- API-ключ для Langflow хранить в `LANGFLOW_API_KEY`.
- Создать класс `LangflowClient` с методами:
  - `async def get_all_flows()` — возвращает список всех flow.
  - `async def run_flow(flow_id, input_value, session_id=None)` — запускает flow и возвращает результат.
- В ответе от Langflow может быть тег `<think>...</think>` или `...</think>`— его нужно вырезать и отображать отдельно как «мышление модели».

**3. Модели данных (PostgreSQL)**
- Таблица `flow_publications`:
  - `flow_id` (string, primary key) — ID flow из Langflow.
  - `is_published` (boolean) — опубликован ли.
  - `published_at` (timestamp) — дата публикации.
  - `updated_at` (timestamp) — дата обновления.
- Использовать SQLAlchemy async.

**4. Публичный дашборд (главная страница)**
- Эндпоинт `GET /` возвращает HTML-страницу со списком опубликованных агентов.
- Агенты — это flow из Langflow, у которых в таблице `flow_publications` стоит `is_published = True`.
- Для каждого агента отображать: название, описание, иконка (пока заглушка `🤖`), при клике — переход на `/chat/{flow_id}`.
- Если нет опубликованных агентов — показывать сообщение «Нет доступных агентов».

**5. Страница чата**
- Эндпоинт `GET /chat/{flow_id}` — отображает страницу чата с этим агентом.
- На странице: заголовок с именем агента, область сообщений, поле ввода, кнопка отправки, кнопки «DeepThink» (показывает/скрывает блок мышления) и «Search» (заглушка).
- При отправке сообщения:
  - Клиент отправляет POST на `/chat/{flow_id}/send` с JSON `{"message": "текст"}`.
  - Сервер проверяет, что flow опубликован, затем вызывает `LangflowClient.run_flow`.
  - Полученный ответ парсится: извлекается текст ответа и блок мышления (если есть), возвращается JSON `{"text": "...", "thinking": "..."}`.
- Использовать библиотеку `marked` на клиенте для рендеринга Markdown.

**6. Административный интерфейс**
- Эндпоинт `GET /admin` — защищён сессией.
- Получить достиуп к эндпоинту можно введя логин и пароль из `.env` файла.
- На странице отображается таблица всех flow из Langflow с колонками: ID, Название, Описание, Статус (Опубликован/Нет), Действие (кнопка «Опубликовать/Снять»).
- Кнопка отправляет AJAX-запрос на `/admin/publish` с телом `{"flow_id": "...", "publish": true/false}`.
- После успешного ответа страница перезагружается.
- Эндпоинт `POST /admin/publish` обновляет запись в таблице `flow_publications` и возвращает `{"status": "ok"}`.

**7. Прочее**
- Использовать переменные окружения из файла `.env` (пример приложить).
- Логирование должно быть информативным для отладки (использовать стандартный модуль `logging`).
- В коде должна быть обработка ошибок (например, если Langflow недоступен — показывать пустой список).
- Шаблоны должны быть вынесены в папку `app/templates/` и использовать Jinja2.
- Для рендеринга шаблонов использовать ручной `Environment` с отключённым кэшем (чтобы избежать ошибок с кэшированием).
- Приложение должно запускаться командой `uvicorn app:app --host 0.0.0.0 --port 5001`.

### Инструкция по запуску

1. Установить PostgreSQL и создать базу `ai_shop`.
2. Запустить тестовый LDAP-сервер (например, в Docker) с пользователем `testuser` и паролем `password`.
3. Установить зависимости: `pip install -r requirements.txt`.
4. Создать файл `.env` с правильными настройками.
5. Запустить приложение: `python run.py` или `uvicorn app:app --host 0.0.0.0 --port 5001`.
6. Открыть в браузере `http://localhost:5001` — увидеть главную страницу.
7. Перейти на `/admin` — будет редирект на логин.
8. Войти с `testuser` / `password`.
9. В админке опубликовать любой flow (предварительно должен быть запущен Langflow с созданными flow).
10. Вернуться на главную — увидеть опубликованного агента.
